# Instalación de JAAK Pulse con `get-pulse.sh`

`get-pulse.sh` instala el bundle completo de JAAK Pulse (**pulse-api + pulse-web**) en
una VM Linux **tuya**, en modo **nativo**: binarios gestionados por systemd y nginx como
reverse proxy. Es la alternativa ligera al [despliegue con Terraform en OCI](/docs/pulse/guia-cliente):
tú aportas la máquina y tu base de datos Oracle 26ai, y el script hace el resto.

> **Descarga directa:** [get-pulse.sh](/docs/pulse/get-pulse.sh)

## Prerrequisitos

- **VM Linux Ubuntu/Debian** con acceso `root` (o `sudo`).
- **Oracle 26ai con AI Vector Search** accesible desde la VM, y su **DSN** a mano, p.ej.
  `oracle://user:pass@host:1522/service?ssl=true&ssl%20verify=false`.
  El instalador **no** instala ni levanta Oracle (BYO base de datos).
- **License key de JAAK** con entitlement PULSE (`JAAK_LICENSE_KEY`).
- Salida HTTPS hacia `api.licensing.jaak.ai` (descarga de releases firmados).
- Puertos **80/443** disponibles en la VM.

## Instalación rápida (interactiva)

```bash
curl -fsSL https://www.jaak.ai/docs/pulse/get-pulse.sh | sudo bash
```

El script pide de forma interactiva:

- `JAAK_LICENSE_KEY` — tu license key con entitlement PULSE.
- `ORACLE_DSN` — el DSN de tu Oracle 26ai.
- `LICENSING_URL` (default `https://api.licensing.jaak.ai`) y el `server_name` de nginx.
- `ADMIN_EMAIL` — email del usuario admin del dashboard (default `admin@pulse.local`).
  El password del admin se genera automáticamente y se muestra al final de la instalación.

## Modo desatendido

Para automatizar (CI, provisioning), pasa la configuración por variables de entorno y
usa `--yes`:

```bash
JAAK_LICENSE_KEY=LK-xxxx \
ORACLE_DSN='oracle://user:pass@host:1522/service?ssl=true&ssl%20verify=false' \
ADMIN_EMAIL=admin@miempresa.com \
  curl -fsSL https://www.jaak.ai/docs/pulse/get-pulse.sh | sudo bash -s -- --yes
```

`ADMIN_EMAIL` y `ADMIN_PASSWORD` son **opcionales**. Si no se define `ADMIN_EMAIL`, se
usa `admin@pulse.local`. Si no se define `ADMIN_PASSWORD`, el instalador genera uno
aleatorio y lo muestra una sola vez al final.

Flags disponibles:

| Flag | Descripción |
|---|---|
| `--yes` | No pregunta nada; falla si falta configuración obligatoria |
| `--licensing-url <url>` | URL del licensing (default `https://api.licensing.jaak.ai`) |
| `--server-name <name>` | `server_name` de nginx |
| `--admin-email <email>` | Email del admin del dashboard (default `admin@pulse.local`) |
| `--create-admin` | Modo post-instalación: crea o rota el admin sin reinstalar |
| `--help` | Ayuda |

Precedencia de configuración: **flags > variables de entorno > prompt interactivo
(si hay TTY) > error**.

## Secrets desde OCI Vault (infraestructura manual)

Si creaste la infraestructura a mano (VM + base + Vault, sin el
[stack Terraform](/docs/pulse/guia-cliente)) y guardas tus secretos en **OCI Vault**, el
patrón recomendado es un **wrapper que lee los secrets con OCI CLI y se los pasa al
instalador como variables de entorno**. No hay que instalar y luego modificar nada: el
instalador escribe los valores en `/opt/jaak-pulse/.env` (0600) y el servicio lee ese
archivo — la aplicación **no consulta el Vault en runtime**.

Solo dos valores son entrada del instalador: `JAAK_LICENSE_KEY` y `ORACLE_DSN` (que
incluye el password de la base). El resto (`JWT_SECRET`, `API_KEY`, `SERVICE_KEY`) los
genera el propio instalador; no hace falta guardarlos en el Vault.

Opcionalmente, `ADMIN_PASSWORD` también puede inyectarse desde Vault si se desea un
valor gestionado (en lugar del password autogenerado).

```bash
#!/usr/bin/env bash
set -euo pipefail

get_secret() {
  oci secrets secret-bundle get --secret-id "$1" --stage CURRENT \
    --auth instance_principal --output json \
    | jq -r '.data."secret-bundle-content".content' | base64 -d
}

DB_PASSWORD="$(get_secret ocid1.vaultsecret...db-password)"
JAAK_LICENSE_KEY="$(get_secret ocid1.vaultsecret...license-key)"

# Escapar caracteres especiales del password para la URL
DB_PASSWORD_ESC="$(python3 -c 'import urllib.parse,sys; print(urllib.parse.quote(sys.argv[1], safe=""))' "$DB_PASSWORD")"

export JAAK_LICENSE_KEY
export ORACLE_DSN="oracle://admin:${DB_PASSWORD_ESC}@<host>:1522/<service>?ssl=true&ssl%20verify=false"

curl -fsSL https://www.jaak.ai/docs/pulse/get-pulse.sh | sudo -E bash -s -- --yes
```

Para que `--auth instance_principal` funcione, la VM debe pertenecer a un *dynamic
group* con esta política:

```
Allow dynamic-group <grupo> to read secret-family in compartment <compartment>
```

Alternativa: correr OCI CLI con credenciales de usuario (`~/.oci/config`) y quitar el
flag `--auth instance_principal`.

Notas:

- El instalador es idempotente, pero **cada ejecución regenera `JWT_SECRET`** (invalida
  sesiones activas del dashboard; sin más impacto) y el **password del admin** (igual
  que `JWT_SECRET`: el seed hace upsert y rota el valor si el usuario ya existe).
- Si rotas el password de la base en tu Vault, **re-ejecuta el wrapper** para regenerar
  el `.env` — la API no toma el valor nuevo sola.

## Inspeccionar antes de ejecutar (recomendado)

`curl … | bash` ejecuta código remoto. Aunque el script se sirve por HTTPS y los
**artefactos que descarga se verifican siempre con minisign + sha256** (la confianza no
depende del canal), puedes revisarlo primero:

```bash
curl -fsSL https://www.jaak.ai/docs/pulse/get-pulse.sh -o get-pulse.sh
less get-pulse.sh
sudo bash get-pulse.sh
```

## Qué hace el instalador

1. Instala prerrequisitos (`nginx`, `jq`, `minisign` pinneado por sha256, …).
2. Escribe `/opt/jaak-pulse/.env` (permisos `0600`) con tu configuración y secretos
   efímeros (`JWT_SECRET`, `API_KEY`, `SERVICE_KEY` y `ADMIN_PASSWORD` generados
   con `openssl` o aportados por env/flag; `ADMIN_EMAIL` por flag/env/prompt,
   default `admin@pulse.local`).
3. Descarga **pulse-api** y **pulse-web** firmados desde licensing-api y los verifica
   (minisign + sha256).
4. Ejecuta las migraciones (`migrate` + `seed`) contra tu Oracle. El **seed** crea el
   usuario admin del dashboard con `ADMIN_EMAIL` / `ADMIN_PASSWORD`.
5. Configura systemd (`jaak-pulse-api`, `jaak-pulse-updater.timer`), nginx
   (`/` → web estática, `/api/` → `127.0.0.1:8787`), sysctl/limits, y abre 80/443.
6. Verifica `http://localhost/healthz` y `/api/healthz`.

Es **idempotente**: es seguro re-ejecutarlo. Las actualizaciones posteriores las aplica
automáticamente `jaak-pulse-updater.timer` (cada 30 minutos), no este script — detalle
en [Actualizaciones (OTA)](/docs/pulse/actualizaciones).

## Primer inicio de sesión

El instalador crea el usuario admin del dashboard. Las credenciales se muestran al final
de la instalación (bloque **Primer inicio de sesión**) y quedan en
`/opt/jaak-pulse/.env` con permisos `0600`.

1. Abre `http://<vm>/` en el navegador.
2. Inicia sesión con el `ADMIN_EMAIL` y el `ADMIN_PASSWORD` impresos.
3. El dashboard **no** ofrece cambio de contraseña self-service. Para rotar el
   password del admin, re-ejecuta el modo post-instalación:
   `sudo bash get-pulse.sh --create-admin` (cada re-ejecución completa del
   instalador también lo rota).

Cada re-ejecución completa del instalador regenera y muestra un password nuevo (igual
que `JWT_SECRET`): el seed hace upsert y rota el password si el usuario ya existe.

## Crear o rotar el usuario admin (post-instalación)

Para instalaciones hechas con una versión anterior del script (sin usuario admin) o para
rotar el password sin reinstalar:

```bash
curl -fsSL https://www.jaak.ai/docs/pulse/get-pulse.sh -o get-pulse.sh
sudo bash get-pulse.sh --create-admin --admin-email admin@miempresa.com
```

Este modo **no reinstala nada**: actualiza `.env` y re-ejecuta el seed (upsert; si el
usuario existe, rota su password). Al final imprime las credenciales nuevas.

## Post-instalación

```bash
journalctl -u jaak-pulse-api -f           # logs de la API
systemctl status jaak-pulse-updater.timer # estado del updater automático
```

Todo queda bajo `/opt/jaak-pulse/` (binarios en `bin/`, web en `web/`, releases en
`releases/`, configuración en `.env`).

## Alcance

Fuera de alcance de esta versión: Oracle empaquetado, desinstalación automática
(`--uninstall`), distros no-apt (RHEL) y TLS/certbot automático (configura TLS en tu
nginx o balanceador).
